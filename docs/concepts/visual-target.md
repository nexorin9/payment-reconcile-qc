# 视觉目标卡 · 支付对账数据质检系统

> 交付形态：**常驻服务 + 浏览器实时界面**（浏览器打开即用，数据到达即刷新）。
> 本卡是 Phase 1 产出的设计目标，**不是**实测截图。真实运行画面见 `docs/screenshots/`。
> 本环境不具备图像生成能力，故只保留结构化视觉目标卡，不伪造概念图。

## 三态画面

### 1. 起始态（刚打开，未选账期）

- 浏览器停在 `127.0.0.1:8788`，顶栏是产品名与账期选择器（未选中，灰态）。
- 左栏六个渠道卡片：微信支付 / 支付宝 / 银联 / 自助机 / HIS / 医保。
  每张卡此刻只有：渠道名、**上次扫描时间**、一个灰态徽标「未扫描」。
- 中栏与右栏空态文案：「本期账期未选择」/「暂无处置结论」。

### 2. 首个可用瞬间（选定 2026-W36 并触发扫描）

- 左栏六张卡**依次**由灰 → 黄 → 绿翻转，每张卡下方一行等宽小字：
  `笔数 1284 / 合计 ¥43,210.55 / fail 3`。
- 顶栏一条 2px 细进度条推进，文案「已扫 4/6 渠道」。
- 中栏差异区**逐行追加**（不整页刷新，视觉上像往下滚）：
  首行「微信支付：3 笔跨日切分重复计入，合计 ¥126.00，证据行 214-216」。

### 3. 成形态（扫描完成，进入处置）

- 三栏定稿：
  - **左「渠道扫描态」**：六卡固定，每卡一个主态色徽标
    （绿=口径全过 / 黄=有待归因单边账 / 红=有未确认 fail / 灰虚线=本期未取到并显示错误码）。
  - **中「差异与成因台账」**：全屏最显眼。差异行字号最大，每行左侧 4px 竖条为成因色块：
    `重复计入` 橙 / `漏传` 红 / `跨日切分` 黄 / `退费未红冲` 紫 / `金额精度` 灰 / `待人工判定` 蓝。
  - **右「已确认结论流」**：经办人确认记录逐条追加，底部固定「导出周对账结论单」按钮与事件链指纹（`sha256` 前 12 位）。

## 视觉语言

| 项 | 取值 |
|---|---|
| 底色 | `#0f1419` |
| 卡片底 | `#1a2129` |
| 正文 | `#c9d4de` |
| 主强调色 | 青 `#3fb8af` |
| 成因色块 | 红 `#e5534b` / 橙 `#e08c3b` / 黄 `#d9c04a` / 紫 `#9a7fd1` / 灰 `#7d8a97` / 蓝 `#4a9de0` |
| 字体 | 标题 `system-ui, "PingFang SC"`；金额与行号 `ui-monospace, "Sarasa Mono SC", monospace` |
| 信息层级 | 中栏差异最显眼（行左侧 4px 成因竖条 + 最大字号）→ 左栏渠道态 → 右栏结论流 |
| 留白密度 | 中等：行高 28px，区块间距 24px |

## 必须可达的约束

- 只做**服务端推实时**（SSE；轮询为降级）+ 纯静态 HTML/CSS + 少量原生 JS。
- **不引入**前端框架构建链；不做 WebGL / 图表库炫技。
- 金额一律以十进制字符串渲染（`Decimal` 精度），**不使用浮点**。
- 不做 Pyodide 之类浏览器内运行时。
